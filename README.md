# Audio Stem Splitter

A command-line research tool for separating a music mixture into instrument stems
with Demucs and evaluating the estimates against known reference stems.

## What the project records

Every separation run receives a unique name and stores:

- separated audio stems;
- run settings and elapsed time in JSON;
- a row in `experiments/experiment_history.csv`;
- logs from the separation process;
- optional objective evaluation results when references are supplied.

## Installation

Create and activate a virtual environment, then install the dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Run commands from this directory, the project root.

## Separate a recording

```powershell
python -m app.main samples/test.wav --model-name htdemucs --run-name baseline
```

Useful model/settings examples:

```powershell
python -m app.main samples/test.wav --model-name htdemucs_ft --shifts 2 --run-name ft_shift2
python -m app.main samples/test.wav --model-name htdemucs_6s --shifts 4 --run-name six_stem_shift4
```

The outputs are written below `outputs/<model>/<run_name>/`. The `outputs`
directory is ignored by Git because audio results can be large.

## Prepare reference stems

Objective evaluation requires ground-truth stems, not stems generated by another
separator. Put one song's references in a directory such as:

```text
references/
└── song_name/
    ├── vocals.wav
    ├── drums.wav
    ├── bass.wav
    └── other.wav
```

Reference audio is ignored by Git. Make sure you have the right to use the chosen
dataset and keep its original license/citation information separately.

For a default identity comparison, filenames in the estimate and reference
directories must match. Files may have different sample rates; they are resampled
to the reference rate. Mono/stereo differences are handled automatically. A
duration mismatch larger than one second is rejected by default to prevent an
invalid comparison.

## Separate and evaluate automatically

Pass the ground-truth directory to the normal separation command:

```powershell
python -m app.main samples/test.wav `
  --model-name htdemucs `
  --run-name baseline_with_metrics `
  --reference-dir references/test
```

This creates `evaluation.json` beside the run outputs and archives a copy in
`experiments/evaluations/`. The aggregate metrics are appended both to the normal
experiment record and to `experiments/evaluation_history.csv`. The latter contains
only objectively evaluated runs and is the main comparison table.

## Compare 6-stem output with 4-stem references

Stem definitions must be identical for a valid comparison. In particular,
`htdemucs_6s` separates guitar and piano from `other`, while a four-stem reference
usually includes them in `other`. Use the provided mapping to recombine them:

```powershell
python -m app.main samples/test.wav `
  --model-name htdemucs_6s `
  --run-name six_stem_mapped_to_four `
  --reference-dir references/test `
  --evaluation-mapping configs/mappings/demucs_6s_to_4s.json
```

The mapping format is reference stem to one or more estimated stems:

```json
{
  "vocals": ["vocals"],
  "drums": ["drums"],
  "bass": ["bass"],
  "other": ["other", "guitar", "piano"]
}
```

Mapped estimates are summed before evaluation.

## Evaluate existing stems without rerunning Demucs

```powershell
python -m app.evaluate `
  outputs/htdemucs/run_name/stems `
  references/test `
  --mixture-file samples/test.wav `
  --output-file experiments/evaluations/manual_test.json
```

For a mapped six-stem result:

```powershell
python -m app.evaluate `
  outputs/htdemucs_6s/run_name/stems `
  references/test `
  --mixture-file samples/test.wav `
  --mapping-file configs/mappings/demucs_6s_to_4s.json `
  --output-file experiments/evaluations/six_stem_manual_test.json
```

Standalone evaluations are also appended to
`experiments/evaluation_history.csv`. When the stem folder has a sibling
`metadata.json`, model name, shifts, segment, device, and run name are copied into
the comparison row automatically. Pass `--history-file ""` if you only want the
detailed JSON.

## Metrics

- **SI-SDR (dB)** measures separation quality while ignoring a global gain
  difference. Higher is better.
- **SDR (dB)** is scale-dependent and therefore also penalizes incorrect output
  level. Higher is better.
- **SI-SDRi (dB)** is the estimate's SI-SDR minus the original mixture's SI-SDR.
  It answers how much the separator improved that stem over doing nothing.

The JSON contains per-stem metrics, macro means and medians, evaluated sample
counts, mappings, missing stems, and unused estimates.

For fair comparisons, use the same mixture, reference files, stem mapping, and
length policy for every run. Do not compare aggregate scores produced from
different songs unless you intentionally aggregate the same dataset for every
configuration.
